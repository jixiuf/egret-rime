# 词库权重、gram 配合与简码设计调研

> 2026-09 调研。数字都来自本机词库实测（egret_wubi_py v6 双词库架构），
> 参考了墨奇、万象、LMDG、雾凇、白霜的设计。统计口径见文末附录。

## 0. 结论

1. 权重要"最合理"，先做到全库一把尺子，再分层缩放，让权重回归语料频次
   真值。现在的架构（log-norm 0-1000、字表 ×0.35、膝点恢复真值）方向对，
   主要缺口在 base.small：词频带宽只有 451 到 5000，中位 525。词与词之间
   几乎没有区分度，组句时词间裁决全推给了 gram，词库层白丢一层信息。
2. gram 用字级的。词级 gram 对混流逐字组合是盲区（Query(台,湾) 实测
   -12，字级 +6.31）。它的角色是裁决没有词库条目的长尾组合；高频表达
   必须词库兜底。
3. 简码用 ownership 单向占位，冲突让位规则写死在 gen 脚本里。2 键空间
   616/625 近满，拼音音节前缀让出约 60 个，3 键靠传统表优先加权重兜底。
   没有采用墨奇式消冲突重排，代价是简码不唯一，换来 86 肌肉记忆兼容。
4. 4 字成语分三层：高频显式入词库，中频靠造词，长尾交给 gram 组句。
   不要全量入库。
5. 简拼（声母缩写）和 2 键空间根本冲突，不做全局简拼。理由见 §5。

## 1. 现状基线（实测数字）

### 1.1 传统库（table_translator@egret_wubi，确定性空间）

| 码长 | 条目数 | 说明 |
|---|---|---|
| 1 键 | 25 | 一级简码，全占 |
| 2 键 | 616 | /625，仅 9 空位 |
| 3 键 | 7,084 | 传统三级码 |
| 4 键(字) | 68,003 | 字全码 |
| 4 键(词) | 63,177 | 2 字词 59,502（2+2 码）+ 3 字词 3,675 |

4 键空间 81,889 个码位里 27,080 个冲突，占 33%。重灾区是生僻字、符号、
日文假名（zzjp 对着ァアィイゥ这一类）。高频段冲突靠权重裁决，表现不错：
等 tffu 780 压过徒增 502，中国 900 压过䟧的 ≈1。这就是"不要按 2+2 冲突
过滤字全码"的数据依据。

词库没有 4 字词。4 字成语现在只有三条路：传统库 encoder 造词（打过一次
才有）、混合库 LM 组句、手工 user_phrases（生不逢时 tgtj）。

### 1.2 混合库（script_translator + LM，概率空间）

| 表 | 条目 | 码长分布 | 权重 |
|---|---|---|---|
| chars_wubi_py_x035 | 120,076 | 3 码 66,045 / 4 码 54,031 | 知频 log-norm×0.35，膝点 600 恢复真值 |
| wb86_wangxiang base.small | 63,177 | 2 字 + 3 字 | 451-5000（万象原值截断） |
| pinyin_8105 | 9,073 | 全音节 | 同音异调合并 |
| pinyin_base_small | 63,793 | 全拼 | 同上 |

混合库 3 码展开后 11,935 个码位，其中 9,032 个多字冲突。这是设计使然：
混合库本来就是概率裁决空间，冲突交给 owner 置顶、拼音接管、LM/权重
三层处理，不需要消冲突。

base.small 的权重带宽 451 到 5000，一个数量级出头；知频字权重 0 到
1000 跨三个数量级。词间区分度明显弱于字间区分度，这是我说的最大缺口。

### 1.3 裁决顺序（dynamic_translator）

```
first  传统库精确码（简码/全码/词组，形码确定性）
then   custom_phrase（用户词组）
then   混合库 script_translator（五笔+拼音混流，LM 组句）
last   type=completion 补全候选
```

## 2. 词库权重

### 2.1 三条已经验证过的规则

第一，全库一把尺子。字、词、五笔、拼音在同一 log 刻度上。知频
（0-1500万）和万象（0-1000）混排的教训：LM 的加减分在 log 尺度上
±10 左右，权重差相差几个数量级时它根本管不着，组句直接失效。

第二，刻度统一归统一，层级另算。统一刻度解决"可比"，但词还是要系统
性高于字，否则组句被单字碾碎（"今天的天气"变"今天在有天气"的教训）。
现在字表 ×0.35，本质是用缩放系数表达"词优先于字"。

第三，频次真值优先。权重应该回到语料频次的单调函数上，log-norm 形状
合适：头部拉开，长尾压平。

### 2.2 词频带宽问题

base.small 的 451-5000 截断是为了滤碎片词，副作用是保留下来的 6.3 万
词彼此权重几乎一样。改法：

- 词权重用语料频次（知频词表或腾讯词频）做 log-norm 回 0-1000，
  替换万象整数值。
- 碎片词过滤不再用频次一刀切，改 LMDG 那套滑动窗口搭配打分，
  看"词+上下文"的共现证据。
- 高频 5000 词（覆盖日常九成输出）拉开权重差，让首候选由词库定；
  长尾压到同一低带，排序交给 gram。字库裁决字，词库裁决高频词，
  gram 裁决剩下的。

### 2.3 目标形态的权重表

| 层 | 来源 | 归一 | 说明 |
|---|---|---|---|
| 一级简码 25 | 固定 | 1000+ | 永远置顶 |
| 二级简码 616 | 固定 owner | 900-1000 | 手感层，不参与概率 |
| 超高频字(≥膝点) | 知频 | 600-1000 | 与词同尺度竞争 |
| 高频词 5k | 语料词频 | 400-1000 | 词库裁决主力 |
| 常用字(<膝点) | 知频×0.35 | ≤210 | 让位拼音/词 |
| 常用词 60k | 语料词频 | 100-400 | gram 裁决区间 |
| 长尾/生僻 | 常数 1 | 1 | 只走补全/反查 |

把"谁该赢"编进权重梯度，gram 只需要处理梯度内分不出胜负的邻近对。

## 3. gram 怎么配合

### 3.1 词级和字级的适用面（实测）

| | 词级(wanxiang-lts) | 字级(essay-bgc / 自训) |
|---|---|---|
| 键结构 | 分词序列 | 字符 n-gram |
| 混流逐字组合 Query(台,湾) | -12（盲区） | +6.31 |
| 高频整词搭配（生姜/可以） | 稳 | 稍弱 |
| 21 例混流批 | 15/21 | 16/21 |

本方案以逐字混流为主，字级 gram 是正确选择。理论上限是字级 2-6gram
加现代大语料自训，jixiuf gram 走的就是这条路（文件遗失，待重训）。

### 3.2 gram 能做什么，不能做什么

能做的：长尾组合裁决。逐字或混流组合没有词库条目时，n-gram 证据定
胜负。non_collocation -12 这个罚分大约能翻转半个数量级的静态权重差，
配合 §2 收窄后的词带是够用的。跨段上下文也在（contextual_suggestions
加 commit_history），collocation_max_length 可以再调。

不能做的：

- 高频整词。传统词库有条目的（可就、生姜类），first_early 置顶，
  gram 无从参与。这是形码确定性的设计，不是 bug。
- 让 gram 仲裁"传统词组 vs 拼音组合"需要统一 quality 尺度，Sentence
  的 log 值和 phrase 的 exp 值不可比。要动就得上 always_make_sentences
  补丁加重排 lua，是产品级决策。
- 语料配比决定 LM 口味。想翻转某个裁决，要么补语料重训，要么词库
  或全码强制。

### 3.3 配合架构

维持现在的三层，微调不大：

```
词库层   高频整词显式条目（传统库确定性 + 混合库"混合拼写"词条批量生成，
         如 台湾 ck wan 900，词级 gram 下也能命中）
gram 层  字级 gram 管一切无条目组合；penalty 调优交给评测数据
机制层   dynamic_translator 三层分组（已就位）；completion 沉底（已就位）；
         always_make_sentences 开不开，等评测说话
```

## 4. 1-4 码简码

### 4.1 空间账本

1 键 25 个全占，无冲突。传统库显式条目，混合库不发纯字母 token
（避免 e=有 vs 额）。

2 键 625 个，传统二级简码占 616。其中是拼音音节前缀的（yi/de/ren
这一类，约 60 个）不设五笔 owner，拼音接管。这里有一个关键取舍：
86 二级简码肌肉记忆 vs 简拼能力，本方案选了前者。

3 键靠两条规则消解：owner 逗号 token 派生保留，被降级字不复用
reserved3 拼写。prism 一字多音节的非确定性问题就是这么绕开的
（历史坑 #3）。

4 键不做简码，纯全码/词码空间，33% 冲突率但高频段无感。

### 4.2 和墨奇方案的对比

墨奇的做法（deal_super_Njian_no_conflict.py）是按词频贪心分配简码，
冲突时低频者让位换码，追求每个简码唯一、可盲打。代价是简码表偏离
传统 86 表。

| | 墨奇式消冲突 | 本方案 ownership |
|---|---|---|
| 简码唯一性 | 100% 确定 | 2 键确定，3/4 键概率 |
| 86 肌肉记忆 | 重排，破坏 | 兼容 |
| 学习成本 | 重新背简码 | 零 |
| 与拼音共存 | 另设计 | 音节前缀天然接管 |
| 实现成本 | 离线分配脚本 | gen 脚本 30 行 |

我的看法：混流用户的注意力已经花了一份在"五笔还是拼音"上，简码层
再引入一套要重新学的编码不划算，ownership 是对的。墨奇那套贪心分配
可以拿来交叉验证：查一查被拼音接管的那约 60 个 2 键里，有没有埋着
字频极高的字（某字 2 键被 yi 类音节占走，但它比该音节打头的高频词
更常用，可考虑三级码提前）。

### 4.3 简码规则固化

1. 一级简码 25 个，传统库显式条目，混合库绝不发纯字母 token。
2. 二级简码：owner 保留逗号 token（派生 2/3 码），其余字降级到传统
   三级码；p2 ∈ pinyin2 的前缀不设 owner。
3. 字全码和二字词 2+2 码冲突：传统库不过滤（权重裁决，等 tffu 实证）；
   混合库过滤（word_codes 集合让位，为 LM 分段保洁净）。两处语义
   不同，改 gen 脚本时不要混同（历史教训 #11）。

## 5. 简拼为什么不做

简拼需要 2 键空间映射高频词首字，而 2 键空间已 98.6% 被二级简码占了。
更麻烦的是，简拼串本身往往就是合法音节的前缀（sj 不是，但 si/so/su
是），每输一个简拼都同时是"没输完的五笔简码"和"没输完的音节"。
三重歧义：对二级简码、对音节补全、对混流分段。单字母 fuzz 简码
早就删过一次（"qshi 组出解析上海"），是同一类问题。

替代方案，按侵入度排：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 不做 | 靠音节前缀+LM，二字词输全拼 2-4 键 | 无 |
| B. 显式触发 | 简拼加 / 前缀（/sj），走独立 tag+lua 翻译器 | 多一键，零冲突 |
| C. 声母束词条 | 只给 top 2000 词生成首字母束拼写，权重压低 | 增噪路径，需评测 |
| D. gram 兜底 | 简拼组合交给字级 gram 组句 | 头部词不确定，手感差 |

A 为主。真有需求加 B。C 和 D 不要做全局。

## 6. 4 字成语

现状词库零 4 字词，既有三条路已覆盖长尾。系统设计分三档：

高频显式。用语料统计取 top 3000 左右（一石二鸟、不可思议这一级），
显式入传统词库（AaBaCaDa 显式码）或混合库。注意 AaBaCaDa 会和
6.8 万字全码、6.3 万词码抢 4 键空间，冲突率从 33% 再涨几个百分点，
靠权重裁决（成语频次对生僻字频次几乎总赢）。收录标准宁缺毋滥，
滑动窗口打分比频次阈值可靠。

中频造词。encoder AaBaCaDa 已配好，打一次自动记住，五笔传统优势，
不用新建机制。注意回归测试前清 userdb。

长尾组句。剩下的交给字级 gram。四字格的 n-gram 证据在语料里通常
充分，essay-bgc 实测 16/21 说明此路基本通。

取舍点在显式收录还是组句：显式确定、快，但每条占一个 4 键码位，
多一个潜在冲突；组句零码位成本，首候选看语料证据。我的经验阈值：
语料频次每百万字 3 次以上（top 数千）才值得显式收录。

## 7. 取舍总表

| 议题 | 选项 A | 选项 B | 本方案立场 |
|---|---|---|---|
| 简码哲学 | 墨奇式唯一简码 | 传统表+ownership | B |
| 字全码 vs 2+2 词码冲突 | 过滤让词 | 权重裁决 | 传统库 B，混合库 A（语义不同） |
| 简拼 | 全局声母缩写 | 音节前缀+显式触发 | 后者 |
| 4 字成语 | 全量词库 | 高频词库+造词+组句 | 后者（3000 显式封顶） |
| gram 角色 | 仲裁一切 | 词库定头部、gram 管长尾 | 后者 |
| 词级 vs 字级 gram | 词级 | 字级 | 字级 |
| 让 LM 仲裁传统词组 | always_make_sentences 开 | 保持形码确定性 | 等评测 |
| 词频带宽 | 万象原值(451-5000) | 语料 log-norm 重归一 | 后者 |

## 8. 行动建议

按性价比排序：

1. 词权重回归真值。知频/腾讯词频对 base.small 做 log-norm 重归一，
   碎片词过滤改滑动窗口搭配打分。首候选确定性和 gram 裁决质量同时受益。
2. 混合拼写词条批量生成。高频二字词"首字五笔 2 码+次字拼音"入混合库
   （台湾 ck wan 路线已原型验证），补词级 gram 盲区。
3. 高频成语 top-N 显式化。语料打分取 top 3000 左右入传统词库，
   regression 加 schema-compare 验证 4 键冲突恶化幅度。
4. 自训字级 gram 恢复（jixiuf gram 文件遗失，管线可复跑），
   和 essay-bgc 做 21 例批 AB。
5. 简码交叉验证。用墨奇贪心脚本审计 2 键空间，查拼音接管的 60 个
   前缀里有无值得抢救的超高频字。
6. 评测基建。把 rime-schema-compare 纳入流程，词库/gram 改动都跑
   句子正确率和文字正确率两个指标，别靠手感。

## 附录：统计口径

xlit 成 `@`），`%` 是第二组，`0` 是短全码标记，统计前先展开。
冲突定义：同码位（去掉 token 标记后）对应超过一个词条。
数据源 dicts/ 与 dicts/wb86_wangxiang_cn_dicts/
（2026-09-26 版本）。复算用 python3 读 yaml body 按 \t 切分即可。
